# Spec：Dashboard 的 Mobile layout

> 状态：草稿，待审查。依据是 2026-10-09 的 grilling 讨论和两个原型：`/prototype/mobile-nav` 与 `/prototype/mobile-drawer`，都在 `prototype/mobile-nav` 分支，未提交。
> 术语沿用 `CONTEXT.md`：**Remote**（SSH workspace）、**Tunnel access**、**Mobile layout**。

## Problem Statement

我在电脑上用 `orx up` 跑实验、驱动 agent。离开电脑后，我想用手机看看实验跑完没有、结果怎么样，也想回应 agent 的权限确认或继续给它下指令。

现在的 dashboard 在手机竖屏上基本不能用：
- 侧边栏默认展开，占满整个屏幕。
- 部分页面会横向溢出。
- 桌面应用的下载提示条占掉约 1/6 的屏幕高度。
- 右侧面板（实验、产物、plan）没有适合窄屏的展示方式。

dashboard 目前还只允许 loopback 访问。经 Tunnel access 打开 dashboard 的能力另有一份 spec 负责，本 spec 只解决"在手机屏幕上能不能好好用"。

## Solution

视口宽度小于 768px 时，dashboard 改用一套专门的 Mobile layout。外层结构是"抽屉 + 全屏面板"：

- **主界面**是当前会话的聊天，占满全屏。
- **顶栏**从左到右依次是：
  - 菜单按钮，带待确认数量的角标
  - 会话标题和所属项目
  - 新会话按钮（+）
  - 实验按钮
  - 产物按钮
- **抽屉**从左侧滑出，可以点菜单按钮打开，也可以从左边缘右滑打开。它和桌面侧边栏一致：顶部是"新会话"，下面按项目分组列出会话，每个会话标出运行中、待确认或空闲时间。
- **全屏面板**覆盖整个屏幕，用来显示实验（列表和详情）、产物（只读）、Plan、Subagent（只读）。右滑或点返回按钮关闭。
- 手机上不提供的功能（文件浏览、Git diff、终端、Overleaf、代码编辑），入口直接隐藏。通过链接直接打开这些页面时，显示"仅桌面可用"。

视口宽度 ≥ 768px 时，行为与现在完全一致。

## User Stories

**进入与总体布局**
1. 作为研究者，我想在手机上打开 dashboard 时直接看到最近一次会话的聊天，以便马上知道 agent 在做什么。
2. 作为研究者，我希望手机竖屏下页面没有横向滚动，以便单手上下滑动浏览。
3. 作为研究者，我希望手机上不出现"下载桌面应用"的提示条，以便把屏幕空间留给内容。
4. 作为研究者，我希望离线提示和更新提示在手机上压缩成一行，以便它们不挡住聊天内容。
5. 作为研究者，我希望手机上的深色/浅色主题和桌面版一致，以便不用另外设置。
6. 作为研究者，我希望在平板或横屏宽度（≥ 768px）下仍然使用桌面布局，以便大屏幕不被浪费。
7. 作为研究者，在桌面浏览器里把窗口拉窄或拉宽、跨过 768px 时，我希望当前打开的会话保持不变，以便调整窗口不会丢失上下文。
8. 作为研究者，我希望把 dashboard 添加到手机主屏幕后，它有正确的名称和图标，以便像一个应用那样打开。

**抽屉与会话导航**
9. 作为研究者，我想点左上角的菜单打开抽屉，看到所有项目和各自的会话，以便切换到别的会话。
10. 作为研究者，我想从屏幕左边缘右滑打开抽屉，以便单手时不用去够左上角。
11. 作为研究者，我想点遮罩、左滑，或者选中一个会话来关闭抽屉，以便快速回到聊天。
12. 作为研究者，我希望抽屉按项目分组且可以折叠，和桌面侧边栏一致，以便两端的心智模型相同。
13. 作为研究者，我希望抽屉里每个会话都显示状态（运行中、待确认、上次活跃时间），以便一眼找到需要关注的会话。
14. 作为研究者，我希望当前会话在抽屉里高亮显示，以便知道自己在哪里。
15. 作为研究者，我希望顶栏同时显示会话标题和所属项目，以便不打开抽屉也知道上下文。

**待确认提醒**
16. 作为研究者，当任意会话里的 agent 在等权限确认、plan 审批或提问的回答时，我希望菜单按钮上出现带数字的角标，以便我在实验面板或别的会话里也不会漏掉。
17. 作为研究者，我希望抽屉里等待回应的会话行显示"待确认"，以便直接点进去处理。
18. 作为研究者，我想在手机上直接点"允许/拒绝"、回答问题、审批 plan，以便 agent 不会因为我不在电脑前而卡住。
19. 作为研究者，我希望处理完之后角标数字立即减少，以便确认操作已经生效。

**聊天与输入框**
20. 作为研究者，我想在手机上给当前会话的 agent 发文字消息，以便继续驱动它工作。
21. 作为研究者，我想直接拍照或从相册选图片作为附件，以便把训练曲线、报错截图发给 agent。
22. 作为研究者，我想在手机上使用 `/` 命令和技能，以便触发常用工作流。
23. 作为研究者，我想在手机上切换模型，以便按任务选择合适的模型。
24. 作为研究者，我想在手机上中断或停止 agent 当前的回合，以便及时纠正方向错误的工作。
25. 作为研究者，我希望 plan 模式和权限模式收进输入框的"⋯"菜单，以便需要时能改，平时又不占地方。
26. 作为研究者，我希望手机上没有 `!` shell 和文件附件入口，以便界面简洁，也不误触危险操作。
27. 作为研究者，我希望聊天里的 Markdown、代码块和公式在窄屏下可读，代码块横向滚动而不是撑破页面，以便正常阅读 agent 的回复。
28. 作为研究者，我希望软键盘弹出时输入框保持可见，不被遮挡，以便看见自己在输入什么。

**新会话**
29. 作为研究者，我想点顶栏的"+"一步打开新会话页，以便快速给 agent 布置新任务。
30. 作为研究者，我想从抽屉顶部的"新会话"进入同一个新会话页，以便和桌面版的操作一致。
31. 作为研究者，我希望新会话页默认选中当前会话所在的项目，并能通过底部弹出面板改选项目，以便新任务落在正确的项目里。
32. 作为研究者，我想在新会话页通过底部弹出面板选择 harness 和模型，以便手机上也能控制用哪个 agent。
33. 作为研究者，发送第一条消息后，我希望自动进入这个新会话的聊天，以便接着观察 agent 的进展。

**实验**
34. 作为研究者，我想点顶栏的实验按钮，在全屏面板里看到当前项目的实验列表，每个实验带上最近一次运行的状态，以便知道哪些跑完了、哪些失败了。
35. 作为研究者，我想点开一个实验看详情：状态、分支、描述、运行命令、`result_markdown`，以便在手机上判断结果。
36. 作为研究者，我想在实验详情里看到运行中实验的实时日志尾部（约最后 50 行），以便知道它跑到哪一步、有没有报错。
37. 作为研究者，我想看到同一实验的历次运行列表，并切换查看某一次运行，以便比较重跑前后的结果。
38. 作为研究者，我想在手机上取消一个正在运行的实验，以便及时止损。
39. 作为研究者，我希望实验状态和日志实时更新，不用手动刷新，以便在手机上盯着关键实验。
40. 作为研究者，我想从实验详情右滑或点返回回到实验列表，再返回就回到聊天，以便层级清晰。

**产物、Plan 与 Subagent**
41. 作为研究者，我想点顶栏的产物按钮浏览项目产物，并查看图片、Markdown、PDF，以便在手机上看到实验产出的图表和报告。
42. 作为研究者，我希望手机上的产物只能查看，不能删除，以便避免误删。
43. 作为研究者，我想点聊天里的 plan 卡片，在全屏面板里阅读完整的 plan 并审批，以便在手机上做出决定。
44. 作为研究者，我想点聊天里的 subagent 卡片，在全屏面板里只读地查看子 agent 的输出，以便了解它做了什么。

**仅桌面可用的功能**
45. 作为研究者，我希望手机上看不到文件浏览、Git diff、终端、Overleaf、代码编辑的入口，以便界面只保留在手机上真正可用的东西。
46. 作为研究者，当我在手机上打开一个指向这些功能的链接时，我希望看到"仅桌面可用"的说明和返回入口，而不是白屏或坏掉的布局。
47. 作为研究者，我希望在手机上看不到设置页里需要执行本地命令的按钮，以便不触发在手机上无意义的操作。

**开发者**
48. 作为 orx 的开发者，我希望 Mobile layout 复用桌面版的聊天组件、Markdown 渲染和数据查询，以便功能只实现一次，两端行为一致。
49. 作为 orx 的开发者，我希望桌面布局的代码不因为移动端而增加分支，以便维护桌面版时不用考虑移动端。
50. 作为 orx 的开发者，我希望移动端的导航状态是可以单独测试的纯逻辑，以便不启动浏览器也能验证导航行为。

## Implementation Decisions

**外层结构**
- 新增一个外层组件 **MobileShell**。项目路由按视口宽度在桌面版外层布局和 MobileShell 之间二选一，**768px 是唯一的断点**。
- 桌面外层布局不新增任何移动端分支。
- 数据查询、事件流（SSE）、聊天的 store 和 recovery，以及 workspace 状态，都在两种外层布局之间共享。
- MobileShell 只负责外层结构：顶栏、抽屉、全屏面板栈、新会话页。
- 内层内容直接复用现有组件：聊天面板、Markdown 渲染、实验列表、状态徽标、产物查看、plan 和 subagent 的展示。

**导航状态模块**
- 新增一个纯逻辑模块，作为 MobileShell 的导航状态机。下面的状态形状来自原型 `/prototype/mobile-drawer`，已经去掉了演示用的部分：

```ts
type MobilePanel =
  | { kind: "experiments" }
  | { kind: "experiment"; experimentId: string; runId?: string }
  | { kind: "artifacts" }
  | { kind: "artifact"; path: string }
  | { kind: "plan"; messageId: string }
  | { kind: "subagent"; partId: string };

interface MobileNavState {
  drawerOpen: boolean;
  newSession: { open: boolean; projectId: string } | null;
  panels: MobilePanel[];   // 全屏面板栈；返回 = 出栈
}
// 事件：openDrawer / closeDrawer / selectSession / openNewSession /
// pushPanel / popPanel / viewportCrossed（跨断点：保留会话，清空 panels 与 drawer）
```

- 状态机的规则：
  - 选中会话时，关闭抽屉并清空面板栈。
  - 新会话页默认选中当前会话所在的项目。
  - 视口宽度跨过断点时，保留当前会话，关闭所有面板和抽屉。

**URL 与深链接**
- 当前会话继续由现有的路由参数表达。
- 当前打开的全屏面板复用现有的 `pane` 搜索参数，这样刷新和分享链接后能恢复。
- 如果 `pane` 指向一个仅桌面可用的面板（文件、diff、终端、Overleaf、代码编辑），Mobile layout 显示"仅桌面可用"的占位页，带返回入口。

**抽屉**
- 结构与桌面侧边栏相同：顶部是"新会话"，下面按项目分组、可折叠，会话嵌在各自项目下。
- 会话的排序和项目的折叠状态，与桌面侧边栏共用同一套数据来源和规则。

**待确认计数**
- 待确认指会话中有未解决的 prompt（权限确认、plan、提问）。
- 菜单按钮上的角标显示所有项目的待确认总数，抽屉里对应的会话行标"待确认"。
- 计数来自现有的会话列表和聊天事件流。如果会话列表接口目前没有返回"是否有未解决的 prompt"，就给会话摘要加一个字段，由服务端计算。这是本 spec 唯一可能涉及的 API 改动。

**手势**
- 从左边缘右滑打开抽屉；在全屏面板里右滑执行出栈。
- 手势的起始区域要离屏幕边缘留出一点距离，避开 iOS Safari 浏览器标签页里系统的"后退"手势。
- 所有手势都有对应的按钮，不能只靠手势操作。

**新会话页**
- 新会话页是全屏页面，由顶栏的"+"或抽屉里的"新会话"打开。
- 页面上是输入框，下方用小按钮选择项目、harness 和模型，点开后从底部弹出选择面板。
- 发送第一条消息后，进入新会话的聊天页。
- 会话创建沿用现有的创建接口，不新增接口。

**输入框（Mobile layout 下）**
- 保留：文字、图片附件（使用 `accept="image/*"`，让手机可以拍照或从相册选）、`/` 命令和技能、模型选择、中断/停止。
- 去掉：`!` shell、非图片文件附件。
- plan 模式和权限模式收进"⋯"菜单。

**实验面板**
- 列表页复用现有的实验列表数据和状态徽标。
- 详情页显示：状态、分支、描述、运行命令、`result_markdown`、运行历史、取消按钮（仅在运行中时显示），以及运行中的实时日志尾部。
- 日志尾部数据来自现有的 `run.log` 事件流，只保留最后约 50 行。

**产物面板**
- 只读：可以浏览和查看图片、Markdown、PDF。不提供删除和上传。

**横幅、主题与 PWA**
- Mobile layout 下不渲染桌面应用下载提示；离线提示和更新提示用单行样式。
- 主题沿用现有机制。
- 新增 web app manifest，包含名称、图标、`display: standalone`、主题色。本期不做 service worker，也不做推送通知。

**与 Tunnel access 的关系**
- Mobile layout 只依据视口宽度决定，不承担任何安全职责。
- 能否使用终端、执行命令、选择路径等危险能力，由服务端按是否为 Tunnel access 来判断。这部分属于 Tunnel access 的 spec，本 spec 不改服务端的访问控制。
- 本 spec 在 UI 上隐藏这些入口，只是为了界面合适。

**样式**
- 遵循仓库约定：优先使用 Tailwind 标准工具类和项目主题别名。
- `ui/dist` 需要重新构建并随改动一起提交。

## Testing Decisions

**什么是好测试**
- 只测外部可观察的行为：给定事件序列，得到什么导航状态；给定路由和视口，渲染出哪种外层布局或占位页。
- 不测组件内部结构和样式细节。

**测试接缝**（尽量少，并且放在尽可能高的层级）
1. **导航状态模块**（主接缝）：一个纯函数 reducer，覆盖打开/关闭抽屉、选中会话、面板入栈出栈、新会话页默认项目、跨断点时的状态变化、待确认计数的推导。
   - 先例：`sidebar-layout.test.mjs`、`workspace.test.mjs`，都是 `node --test` 直接导入 `.ts` 纯模块。
2. **路由层**：给定视口宽度和 `pane` 参数，项目路由渲染 MobileShell 还是桌面布局；仅桌面可用的 `pane` 是否渲染占位页。
   - 先例：`routes.test.mjs`，把整个路由模块加载起来，并替换掉 UI 依赖。

**明确不新增的接缝**
- 不为抽屉、顶栏、面板写组件级的快照测试。
- 移动端的视觉验收用 dev slot 加手机尺寸截图人工检查，和这次可行性分析的做法一样。

**CI**
- 按 `.github/workflows/ci.yml` 跑现有检查：`pnpm build` 里包含 i18n 检查、类型检查，另有 style lint。
- 新增的文案必须走 paraglide 并补齐翻译。

## Out of Scope

- **Tunnel access 的服务端部分**：认证方式（token、登录、cookie）、放行的公网 Host/Origin、在 Tunnel access 下拒绝的路由，以及对应的 ADR。这些另开一轮讨论，单独写 spec。
- 平板专用布局、横屏专用布局。
- 推送通知、service worker、离线缓存。
- 飞书机器人集成（可行性分析中的另一条路线）。
- 手机上的文件浏览、Git diff、终端、Overleaf、代码编辑、设置页中的命令执行。
- 实验指标图表（store 里没有 metrics 表）。
- 修复 dev 模式下 paraglide 按消息拆分模块、被广告拦截扩展误拦的问题。这是开发环境的问题，可以单独处理。

## Further Notes

- 原型（不合入 main）：
  - `/prototype/mobile-nav`：三种导航外壳的对比，结论是选 A，抽屉 + 全屏面板。
  - `/prototype/mobile-drawer`：抽屉结构与新建入口的对比，结论是 Q15-A 按项目分组、Q12-B 顶栏加"+"。
  - 两者都在 `prototype/mobile-nav` 分支，未提交。
- 我在可行性分析中实测到的现有问题，可以作为验收对照：
  - 在 390px 宽度下，侧边栏默认展开。
  - 新建任务页横向溢出，scrollWidth 为 536。
  - 侧边栏展开时聊天页溢出，scrollWidth 为 702。
  - 下载提示条约占 1/6 屏高。
- `CONTEXT.md` 是这次新建的，应该随实现一起进入 main。
